# 三角色交接

每次交接带同一 `config_record`（experiment.md 路径）和 `config_sha256`、实验/轮次/attempt 身份、固定 Parent 路径与哈希、输出位置。参数始终回读 MD，交接文件不另存模型、候选数、执行命令或 Gate 默认。相对产物路径按 MD 的工作目录解析。

| 方向 | 必须交付 |
|---|---|
| 监控 → 归因 | Parent、完整 case/trial 清单、结果、全部轨迹、此前反馈 |
| 归因 → 监控 | 逐 case 底表、具体机制簇、证据位置、归因报告、scope、覆盖和选择依据 |
| 监控 → 优化 | 原归因报告、冻结 scope、固定 Parent、经验引用、此前候选与反馈 |
| 优化 → 监控 | 候选清单、每项的假设与主要修改面、完整 YAML、相对 Parent 的真实 diff、record、加载/自检证据 |
| 监控 → 优化/归因 | 对应候选身份、评测完整性、指标和 Gate、原始轨迹、回归 case、实际加载/送达/触发证据 |

候选 record 记录配置 MD、Parent、候选和运行时依赖的身份；实际改动字段、预期行为、反证条件、运行命令与输出、额外开销以及尚未验证的部分。优化经验是决策输入，三角色 skill 是工作流程，被测 Agent 的任务技能是 YAML 中的行为组件，三者不要混用。

分别报告加载有效、请求已送达、组件已触发、行为改变、评测收益。未运行、未触发、未送达、行为未变和执行失败必须区分；不能凭分数倒推组件起效，也不能只凭配置存在声称修改已落实。

缺产物、空 scope 或证据冲突明确交回监控。scope、Parent 和恢复规则由 MD 决定，角色不自行换题或修改实验协议。
