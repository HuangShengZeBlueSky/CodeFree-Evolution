# 一份 Markdown 决定实验配置

监控创建或读取唯一的 `experiment.md`：正文记录决策来源和说明，一个标记为 `yaml experiment-config` 的代码块提供执行配置。沿用已确认参数；缺失项可先沟通，或按用户目标和已验证项目接口选合理默认并注明依据。对任务目标、授权范围或无法推断的接口仍有实质冲突时先解决。其他角色不生成第二套默认，正文与配置块冲突由监控修正。

## 配置内容

| 部分 | 监控必须确定的内容 |
|---|---|
| 身份和运行环境 | 实验 ID、工作目录、运行时版本、解释器、必要环境及凭据引用 |
| 三角色 | 执行方式、模型/生成参数、并发、超时和交接位置 |
| 数据与评测 | benchmark、split、case、trial、seed、日志格式、输入导出、指标与评分入口 |
| 被测 Agent | 完整 Parent YAML 路径和哈希、运行时 Schema、工具/组件实现和政策等依赖身份 |
| 搜索 | 允许修改面及实际字段映射、轮次、attempt、候选数、scope 冻结与反馈策略 |
| 决策与边界 | Gate、晋升时机、排序、合并、重试、停止条件及调用/费用预算 |
| 执行与产物 | 真实的准备、加载、运行、导出、评分入口及输入输出，候选、diff、轨迹和状态位置 |

新实验默认记忆、压缩、任务技能、参数校验、业务校验和结果增强全部启用。监控根据当前任务和已注册组件填入真实的记忆字段/指令、压缩阈值/摘要指令、技能正文、合法校验规则和结果增强内容；`enabled: true` 配空定义不算完成。参数与业务校验按工具能力选适用规则，不把不适用的约束强加给所有工具。确实不适用的工具项可以显式空列表，但每类组件在 Agent 中都须有适用的实际配置。

默认是监控**生成配置时**的选择，必须落成完整 YAML；运行时加载缺字段仍报错。除非用户明确要求消融，候选持续保留全部组件。组件已开启与本次轨迹已触发是两件事，验收需要分别记录。

MD 决定实验怎么跑，完整 Agent YAML 决定被测 Agent 行为。被测模型参数以 YAML 为准；MD 用路径和哈希绑定它，不在命令中另行覆盖。外部政策、工具实现等必须在 YAML 合同中显式绑定并固定依赖身份，不能把源码 docstring、环境变量开关或另一候选当作行为后备配置。命令所需的其他配置只能从 MD 单向派生并标记源哈希。

## 配置骨架

以下只是待填写结构，空映射不代表已有可运行配置：

```yaml experiment-config
schema_version: 1
experiment_id: <本次唯一标识>
workdir: <实际工作目录>
environment: {} # 必要环境；凭据采用环境变量或文件引用
roles: {} # 三角色的执行方式和资源参数
benchmark: {} # 数据范围、trial、seed、输入输出格式
harness: {} # Parent与哈希、运行时版本、Schema、工具/组件/政策/经验依赖
search: {} # 修改面映射、候选策略、scope冻结和反馈规则
scoring: {} # 指标、Gate、晋升时机、排序和合并
limits: {} # 并发、预算、重试、超时、停止条件
artifacts: {} # 所有产物与状态位置
commands: {} # 项目原生执行入口的argv、超时及输入输出
```

命令使用 `argv` 数组、显式 `timeout_seconds`，参数用 `{candidate}` 等命名占位符。可用[通用命令入口](../scripts/experiment_config.py)读取 MD 并执行一条已配置命令；它只解析配置和调用命令，不包含 benchmark 校验规则，也不负责三角色调度。实际解释器由本次 MD 确定。

```text
<解释器> <监控skill目录>/scripts/experiment_config.py <experiment.md> --command <命令名> --set candidate=<候选文件>
```

冻结后改变实验参数须记录新配置身份并生成新运行输出。状态只记录进度，不能覆盖配置。已接入的 benchmark 通过更换本 MD 切换；新接口由项目提供并在 MD 声明，三份角色 skill 不写入项目特例。
