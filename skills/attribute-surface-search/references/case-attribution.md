# 逐 case 分析与聚类

读取监控交接的配置 MD，核对身份、Parent 和完整 case/trial 清单。输入转换、执行方式、模型、并发、类型表、scope 与选题规则都来自 MD；日志格式不兼容时使用其中声明的项目导出入口。

每个 case 阅读全部实际 trial，包括成功对照、完整消息和工具结果。长轨迹可连续分段阅读，记录范围并保留上下文；不静默截断。单 case 工作只返回该项，不再次派发。

沿 Agent 当时可见的信息解释失败：定位具体工具、参数来源、结果字段、步骤或跨轮状态，保留 task/trial/turn 和原始证据位置。分别写观察事实、原因假设、成功反例和缺失证据，不按评分预期动作倒推 Agent 知道的事实。

收齐 case 后核对覆盖，按具体机制聚类；粗问题类型不等于同一修复机制。同一 case 的不同 trial 可以属于不同机制。比较受影响范围、反证、可干预性，按 MD 选择 Target 并说明纳入与排除理由。证据不足保留未知，不为凑候选强行选题。

归因可以建议干预方向，但优化自行从允许范围选择实际修改面。候选反馈回来后，区分配置没加载、组件没触发、内容没送达、行为未变和实际改善/退化；scope 冻结与重新归因时机继续遵守 MD。

交付逐 case 底表、机制簇、归因报告和 scope；输出位置和格式取自 MD。逐 case 子任务退出码为零不等于覆盖完整，覆盖完整也不等于推理正确，需要核对实际内容。
