# 修改面与验证证据

从 MD 的允许修改面选择。下表是机制到方向的参考，实际字段与组件由 MD 引用的 Schema 和实现决定，不把经验名称当成 YAML 键。

| 失败机制 | 修改方向 | 验证修改确实落实 |
|---|---|---|
| 全局行为纪律反复失败 | 系统指令 | 新指令进入主模型请求，冻结政策仍完整 |
| 工具用途、前提或参数来源被误解 | 工具描述 | 请求 description 等于候选文案，参数和其他规则保持完整 |
| 参数格式或范围非法 | 参数校验 | 合法输入放行，非法输入在业务副作用前拦截，错误按 YAML 返回 |
| 状态、所有权或业务前置条件被违反 | 业务校验 | 合法/非法状态分别验证，真实执行与回放一致 |
| 当轮误读正确工具结果 | 结果增强 | 命中与不命中条件都检查，增强进入下次请求且不伪造事实 |
| 后续回合遗忘目标、实体或约束 | 结构化记忆 | 更新事件、前后值和下一次请求中的记忆一致，记录额外开销 |
| 长历史负担或摘要丢失事实 | 压缩 | 足够长历史触发压缩，摘要指令、关键事实和后续请求可核验 |
| 任务族缺少跨步骤程序 | 任务技能 | 技能正文按配置的加载方式送达；目录存在不算已加载 |

每个候选说明假设、预期触发和反证条件。若问题来自 Harness 副作用，修正对应组件，而非先关闭它。选择一个主要修改面便于归因，实际是否允许多面联合由 MD 决定。

当现有 YAML/注册组件无法表达假设时，记录表达能力缺口，交回监控重新选题。不可修改冻结的政策、任务或评分；未知 YAML 键和未注册组件不算完成改进。
