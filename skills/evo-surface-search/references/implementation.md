# 从归因到可执行候选

1. 读取同一 MD、原归因与冻结 scope、完整 Parent、此前反馈；按需回读轨迹，确定可证伪的机制假设。
2. 查 MD 引用的运行时 Schema 和组件实现，定位实际字段。从固定 Parent 复制完整候选，保留其他组件有效并开启；实际写文件，生成相对 Parent 的真实 diff。
3. 用 MD 指定的项目原生加载/测试入口验证结构与行为，保存命令、输出及配置身份。规则和阈值必须适用于真实工具与任务，不能只让 YAML 通过语法检查。
4. 交付候选清单、完整 YAML、diff、record 和证据，明确已加载、已送达、已触发和待评测分别有哪些。正式 benchmark 由监控执行。
5. 读完整反馈再选择保持、改写或换假设。反证需改变 scope 时交回监控和归因，不自行换题。

现有工具描述等 YAML 字段直接可改；新增能力须由既有运行时提供。组件不存在时明确缺少的实现，不用空定义或未知字段伪装完成。不附带某个 benchmark 的 checker；实验执行命令都由监控在 MD 中指定。

归因缺失、运行入口不可用或加载器违反显式合同，应报告具体阻碍并在已授权范围内修复；不能交付只存在于叙述里的候选。组件触发不等于训练收益，收益必须等待监控的真实评测。
